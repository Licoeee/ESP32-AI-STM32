# ESP32-S3-N16R8 硬件开发参考手册 (Standalone)

---

## 1. 核心系统架构

### 核心模组
* **型号**: ESP32-S3-N16R8

### 电源供应 (Power Tree)
* **输入源**: 
    * **USB1 (UART)**: 通过 Type-C 接口供电。
    * **USB2 (OTG)**: 通过 Type-C 接口供电。
    * **5V Pin**: 可通过排针直接输入 5V。
* **稳压电路**: 采用 **CJ6117A330W** (LDO)，将 5V 转换为系统主电压 **VDD33 (3.3V)**。
* **指示灯**: 红色电源指示灯 (PWR LED) 接在 3.3V 回路，通电即亮。

---

## 2. 通信接口与逻辑互连

### 2.1 双 USB 接口逻辑
本开发板设计有两个 Type-C 接口，功能完全不同：

1.  **USB1 (调试接口)**:
    * **核心芯片**: CH343P (USB 转串口)。
    * **连接引脚**: 映射至 ESP32-S3 的 **UART0 (TXD0/RXD0)**。
    * **自动下载**: 集成 DTR/RTS 自动复位电路，无需按键即可通过软件触发进入下载模式。
2.  **USB2 (原生 USB)**:
    * **模式**: 支持 USB-OTG 和 USB-Serial-JTAG。
    * **连接引脚**: **D- (GPIO19)**, **D+ (GPIO20)**。
    * **用途**: 用于模拟 HID 设备（键盘/鼠标）或作为原生调试端口。

### 2.2 板载 RGB 灯 (WS2812B)
* **物理连接**: 单颗 XL-5050RGBC-WS2812B 芯片。
* **控制引脚**: **GPIO48**。
* **驱动要求**: 需使用单总线协议驱动，供电电压为 3.3V。

## 3. 物理引脚分配 (Pinout Map)

开发板通过两侧 22-pin 排针 (Header 22) 引出。

| 功能分类 | 映射引脚 (GPIO/Label) | 详细描述与开发注意事项 |
| :--- | :--- | :--- |
| **系统控制** | EN (CHIP_PU) | 复位引脚，低电平有效。 |
| **系统控制** | GPIO0 (BOOT) | 启动模式配置，也可作为用户按键使用。 |
| **串口 0** | TXD0 / RXD0 | 默认烧录与 Log 输出口，接 CH343P。 |
| **原生 USB** | GPIO19 (D-), GPIO20 (D+) | USB2 接口物理引脚。 |
| **板载 RGB** | **GPIO48** | 唯一控制引脚，驱动时需指定此序号。 |
| **基础 IO** | GPIO1 ~ GPIO14 | 通用数字引脚，支持 ADC/PWM 功能。 |
| **高速总线** | GPIO15, 16, 17, 18 | 适合配置为 SPI 或 I2S 总线。 |
| **敏感 IO** | GPIO35 ~ GPIO40 | **警告**：在某些 WROOM 模组中与内部 Flash 共享，避免作为大电流输出。 |
| **特殊 IO** | GPIO41, 42, 47 | 高位通用引脚。 |

## 4. 关键开发场景索引 (Quick Start for AI)

* **场景：如何烧录代码？**
    * AI 指令：连接 USB1 接口，在工具中选择正确的串口，利用 DTR/RTS 自动电路完成烧录。
* **场景：如何驱动点亮板载灯？**
    * AI 指令：使用 FastLED 或 NeoPixel 库，将 Data Pin 设为 **48**，灯珠数量设为 **1**。
* **场景：如何使用 USB-OTG 功能？**
    * AI 指令：连接 USB2 接口，在代码中使能 TinyUSB 堆栈，相关硬件脚为 **19** 和 **20**。
* **场景：手动进入下载模式？**
    * AI 指令：按住 BOOT 键不放，点击一次 RST 键，最后松开 BOOT 键。

## 5. 后续开发约束

后续基于该开发板进行开发时，请优先遵守以下约束：

1. **USB1 与 USB2 角色分离**
   * USB1 主要用于烧录、串口日志和调试。
   * USB2 主要用于原生 USB/OTG 功能，不要默认把它当成串口下载口。

2. **板载 RGB 灯固定引脚**
   * 板载 WS2812B 的控制脚固定为 **GPIO48**。
   * 涉及板载指示灯、状态灯、启动反馈等功能时，优先复用该引脚信息。

3. **默认烧录与日志口**
   * UART0 仍然是最稳妥的默认输出口。
   * 如果改用其他串口方案，需要同步更新开发文档与调试说明。

4. **高位 IO 使用前先核对硬件连接**
   * GPIO35 ~ GPIO40、GPIO41、GPIO42、GPIO47 等引脚在使用前应先确认是否已被板上其他电路占用。
   * 不要仅凭“可用 GPIO”假设其可直接作为普通输出或大电流驱动脚。

5. **开发前先对照引脚定义文档**
   * 新增外设、修改硬件连接、选择 PWM/SPI/I2C/UART 引脚时，必须先查阅本文件。
   * 若后续原理图或板卡版本变化，应先更新本文件，再开始编码。
